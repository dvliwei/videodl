# 使用 TRAE 落地开发

## 每次开始前

按这个顺序阅读：

1. `AGENTS.md`：项目通用开发约束。
2. `docs/PRODUCT_SPEC.md`：用户范围、产品行为和验收要求。
3. `docs/ARCHITECTURE.md`：代码边界、契约和安全决策。
4. `docs/DEVELOPMENT_PLAN.md`：当前任务及前置依赖。
5. 当前任务涉及的源代码、配置与生成文件。

不要只根据计划推断现状。计划中标为“待实现”的功能不能在交付描述中说成已经完成。

## 推荐工作方式

- 一次只交给 TRAE 一个开发计划任务，不按“阶段”一次性实现整组功能。
- 开始前要求 TRAE 列出将修改/新增的文件、读取的契约、验收方式和潜在冲突；发现计划遗漏时先更新文档再继续。
- 任务实现后检查差异，要求它报告实际运行过的检查及原始失败原因。没有运行的检查标为“未运行”，不能声称通过。
- API、事件、产品范围或 FFmpeg 许可/来源改变时，同步更新 `PRODUCT_SPEC.md`、`ARCHITECTURE.md` 或 `DEVELOPMENT_PLAN.md`。
- `frontend/wailsjs` 是生成物；修改 Go 导出方法后使用当前 Wails CLI 流程重新生成，不手改生成文件。
- 不允许一项任务顺手实现后续任务、替换技术栈或引入组件库/状态库，除非先说明必要性并更新架构约定。

## TRAE 单任务提示词模板

复制后只替换任务编号：

```text
请按仓库 AGENTS.md 和 docs/TRAE_GUIDE.md 工作。

本次只执行 docs/DEVELOPMENT_PLAN.md 中的“任务 N：<任务名>”。先阅读该任务依赖的 PRODUCT_SPEC.md、ARCHITECTURE.md 和现有代码。不要实现后续任务，也不要改变已确认的 MVP 范围。

开始修改前，请先说明：
1. 当前代码状态与该任务的差距；
2. 计划修改/新增的文件及职责；
3. 对应的验收条件和将运行的检查；
4. 是否发现计划、接口或平台约束冲突。

如无冲突，直接完成该任务；如有冲突，先报告具体冲突和最小修订建议。遵循现有依赖，避免无必要依赖和抽象。新增/修改核心逻辑时先补针对性测试。不要手工编辑 frontend/wailsjs 下的生成文件。完成后报告文件变更、验收结果、实际运行的命令和仍未解决的问题；未运行的检查必须明确列出。
```

## 阶段交接检查

- 后端任务：检查 Go 包边界、context 取消、错误码、并发/资源清理和测试覆盖。
- Wails 接口任务：检查参数与 `internal/media` 契约一致，事件带 task ID，取消对话框不产生副作用。
- Vue 任务：检查 loading/empty/error/success 状态、键盘可用性、窄窗口和未知进度显示。
- FFmpeg/打包任务：检查目标 OS/架构、工具版本/哈希、许可材料、无系统 FFmpeg 环境和离线运行。
- 每个任务结束后更新 `docs/DEVELOPMENT_PLAN.md` 的任务状态（如使用复选框），并提供变更摘要，方便后续 TRAE 会话续做。
